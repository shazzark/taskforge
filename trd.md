# Technical Requirements

## CLI contract
Implemented CLI commands include `taskforge run csv-analyze --input <path>`, `taskforge run document-analyze --input <path>`, `taskforge run pdf-report --input <report.json> --output <new.pdf>`, `taskforge run repo-inspect --root <directory>`, `taskforge run source-review --root <directory> --file <relative-path>`, `taskforge run model-investigate --root <directory> --file <relative-path> [...]`, `taskforge run github-issues --repository <owner/name>`, `taskforge run file-patch --root <directory> --target <relative-path> --content-file <relative-path>`, `taskforge run git-diff --root <directory>`, `taskforge run software-check --root <directory> --check <node-test|typescript-check>`, `taskforge resume <run-id> --input <path>`, and `taskforge history list`. CSV and document workflows read one explicitly approved file and store redacted metadata; PDF report output asks approval for the exact target and content hash, creates a new file only, and validates the written hash; document parsing supports TXT, Markdown, text PDF, DOCX, and XLSX and persists aggregate counts only. Resume revalidates input/workflow hashes. Repository inspection requires interactive exact-root approval, inventories bounded metadata only, skips links/secret paths/generated folders, and runs no commands. Source review requires exact root/file-set approval, accepts bounded UTF-8 source only, redacts common credential patterns locally, and sends/persists no source content; its redaction is heuristic. Model investigation displays up to five redacted source files, requests a separate provider-transfer confirmation, sends no tools, and stores neither excerpts nor findings. Public GitHub issue reading asks before one tokenless GET, returns at most 20 validated open issue titles, excludes pull requests, and persists nothing; private-repository access is not implemented. File patching binds replacement content and target snapshot into a preview, displays redacted before/after text, requires explicit approval, then writes through the revalidated open target handle. This preserves permissions and prevents a changed path from redirecting the write; in-place writes are not crash-atomic and cannot coordinate concurrent same-file writers. Git diff review requires approval of the exact canonical root and staged tracked file list, disables external diff/text conversion, caps output at 48 KiB, rejects secret paths, and displays heuristic-redacted source locally without persistence. It excludes unstaged and untracked files. Software checks require separate approval for the exact root and one fixed command; stdout/stderr are drained, bounded, not displayed, and not persisted. The command is not an OS sandbox; tests may run repository code. Other proposed commands include `taskforge "goal"`, `taskforge chat`, `taskforge model-check`, `taskforge workflows list`, `taskforge config`, `taskforge doctor`, `taskforge history delete <run-id>`, and `taskforge schedule list/add/remove`. `model-check` is a synthetic read-only provider/tool contract check. Omitted required inputs trigger questions, never guesses. Exit codes distinguish verified success, failed task, cancellation and setup errors. Support spaces in Windows paths and UTF-8 output. Interactive approval is unavailable in noninteractive runs, so approval-required actions stop.

## Input/tool contract
`taskforge run draft --input <draft.json> --output <new.md>` accepts a bounded JSON object for a GitHub issue draft or email draft and creates a new Markdown artifact after explicit content preview and path/hash approval. It has no external write integration and never sends. The selected Markdown format is a local implementation convention; no email provider or GitHub write credential is used. Create-only protects against overwriting a target occupied at link time; concurrent hostile replacement of the approved parent directory is not protected by Node's path-based filesystem API.

`taskforge run specialist-review --root <directory> --file <relative-path> [...]` accepts up to five locally approved source files and a user-provided goal, then makes up to three calls through the selected provider: at most two fixed read-only specialist roles and one parent review. This CLI command creates one fresh `AgentBudgetLedger` shared across its worker and parent-review calls, bounded by 40 model requests and 30 tool actions (this command exposes no tools). The ledger can also be passed into `runToolLoop` when both are composed in a parent orchestration path; the current CLI command is not attached to a separate ongoing agent run. Specialists receive no tool definitions; any returned tool call is rejected. Nested spawning is unavailable. Worker and parent findings are bounded and labeled unverified; incomplete provider/budget work returns a failure status and nonzero CLI exit. Files/results are not persisted. This initial first slice cannot grant workers file, browser, shell, GitHub-write or email-send tools.

Validate task inputs and tool arguments with runtime schemas. Every tool declares name, description, input schema, access requirements, effect classification, timeout and output limits. Reject unknown tools and invalid arguments. Tool results include status, evidence and bounded output. Treat model responses as untrusted input. Include idempotency identifiers for operations where supported. Persist action intent before mutation and outcome afterward.

## Provisional run budgets
30 tool actions; 40 model requests; 15 minutes of active runtime excluding approval waiting; 3 equivalent consecutive failures. Limits apply across parent and workers, not per agent. Maximum two workers; bounded context and tool-output sizes. Stop at a limit, save progress and offer a deliberate extension. Provider spending ceiling only when usage/pricing can be measured; do not promise exact costs from a request count. Provider quotas remain independent.

## Cancellation and recovery
Ctrl+C requests cancellation, stops new actions, aborts supported requests and terminates child processes with a bounded grace period. Record cancelled or uncertain outcomes. Preserve completed artifacts. Resume validates checkpoint version and current inputs and requires fresh approvals where necessary. Cancellation cannot reverse an already completed external action.

## History recommendation
Save detailed run summaries and redacted, truncated tool events by default, not full chats. Full transcripts are opt-in with disclosure. Proposed defaults: raw events/transcripts expire after 30 days, summaries after 90 days, maximum 5 MB stored event/transcript payload per run; oversized outputs become local artifacts. Artifacts have separate cleanup rules and no implicit TTL deletion. Secret redaction precedes persistence. User deletion removes a run's database records and only its owned artifacts when explicitly requested.

## Checks by capability
Files: path escape, junctions, secret filtering, unchanged-content moves, duplicate-name conflicts. Data: known totals, duplicates, missing values, encodings and malformed CSV. Software: reproduce seeded regression, inspect approved diff and rerun relevant tests. Browser: controlled HTTP errors, failed requests, console failures, broken link and mobile overflow; login checks only with supplied accounts. Research: sources actually retrieved, timestamps, contradiction/unsupported-claim handling. Agents: budget sharing, denied tools, write conflicts and parent review. Scheduling: missed runs, duplicate suppression and approval-required state.

## Security and privacy
No credentials in logs, screenshots intended for sharing, reports, fixtures or Git. Explicit online-transfer disclosure and user choice. Restrict network destinations where needed; protect against private-network access when processing untrusted URLs. Browser tests against localhost require explicitly approved local targets. Avoid rendering untrusted HTML directly into reports. No claim of comprehensive penetration testing or security certification.

## Distribution
Document tested Node version, MongoDB installation/connection, local model and browser setup on Windows. Pin dependencies and commit lockfile. npm package must declare actual files, executable and engine requirements. Validate tarball on a separate Windows consumer project before publishing. MIT covers TaskForge code, not automatic relicensing of model weights or dependencies.
